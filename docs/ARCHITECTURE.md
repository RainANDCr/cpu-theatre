# 架构与决策记录

本文记录已经定下、且后续阶段不应随意推翻的技术决定。每条都写清「为什么」，因为半年后的人
（包括我们自己）只会记得结论，不会记得当时的取舍。

---

## 1. 分层：引擎 / 适配 / 视图

```
src/core/**       纯 TypeScript。不 import React、不 import zustand、不碰 DOM。
src/store/**      Zustand 容器。把引擎输出投影成 UI 需要的最小状态。
src/components/** 只读 store，只发意图（dispatch 命令）。
```

依赖方向严格单向：`components → store → core`。反向依赖一次都不允许。

**为什么**：验收要求「同一段程序分别跑 SEQ 与 PIPE，终态必须完全一致」。这类对拍测试
只有在引擎能脱离浏览器裸跑时才成立。如果执行逻辑寄生在组件里，测试就只能靠点按钮 + 读 DOM，
既慢又脆，而且必然在某个异步渲染时机上出错。

**边界细则**：

- `core/**` 的导出函数接收 `CPUState`，返回新的 `CPUState` 与一个 `trace` 对象；
- `store` 不缓存引擎内部对象，只保存可序列化的投影（cycle、pc、status、最近一条指令等）；
- 组件不允许调用 `useCpuStore.setState` 修改运行时字段，只能调用 store 暴露的 action。

## 2. ADR-001：用 `bigint` 表示 64 位字

**决定**：`type Word = bigint`，每次产生新值都经过 `asWord()` 截断到 64 位。

**理由**：JavaScript 的 `number` 只有 53 位整数精度。Y86-64 的字是 64 位，
`irmovq $0x7fffffffffffffff, %rax` 这类值会在 `number` 上悄悄丢低位，之后
OF/SF 与内存写入全部跟着错，而且错得很安静——最难查的那种。

**代价**：bigint 比 number 慢。对教学规模的程序（几十到几千条指令）完全可接受；
即使 PIPE 每周期跑五条指令，也不构成瓶颈。

**已落地**：`src/core/cpu/word.ts`（`asWord` / `asSigned` / `isNegative` / `toHex` / `toBin` / `fitsInWord`），
配套 8 个单元测试覆盖补码截断、符号位判定、值域边界。

## 3. ADR-002：`erasableSyntaxOnly`，不用 `enum` 与 `namespace`

**决定**：遵守 TypeScript 7 模板的 `erasableSyntaxOnly`，指令码、状态码、寄存器编号
一律用 `as const` 对象 + 联合类型表达。

**理由**：这些语法在编译期会产生运行时代码，无法被纯类型擦除的构建链正确处理。
顺带的好处是：`const ICODE = { HALT: 0, NOP: 1, ... } as const` 在测试里能直接当值用，
比 enum 更适合做「指令表」这种数据驱动的东西。

## 4. ADR-003：不可变状态快照 + 快照/差分混合历史

**决定**：一次执行不修改传入的 `CPUState`，而是返回新对象。执行历史保存
「周期 + 快照」的环形缓冲，超过阈值后改为「基准快照 + 差分」。

**理由**：Step Back 必须精确恢复上一拍的全部字段。把动画倒放不算回退——
寄存器值不会自己倒流。而每拍存全量快照在长程序上会吃掉几十 MB。

**待 Phase 5 落实**：寄存器文件只有 15 个 64 位值（`bigint[15]`），内存改为
「脏页差分」（每 4KB 一页，只记录被写过的页）。这套策略要在 Phase 5 用
「回退 1000 步后内存逐字节相等」的测试来验收，而不是靠肉眼。

## 5. ADR-004：`EngineState` 与 `Stat` 是两个概念

**决定**：`ProcessorStatus = 'AOK' | 'HLT' | 'ADR' | 'INS'` 表示 Y86-64 的 Stat；
`EngineState = 'offline' | 'idle' | 'running' | 'paused' | 'halted' | 'fault'` 表示引擎生命周期。

**理由**：`HLT` 是处理器说「我停机了」，`paused` 是用户说「先别跑」。混成一个枚举，
会出现「HALT 之后暂停按钮变成运行中」这种状态机错乱。顶栏读的是 `EngineState`，
学习面板与日志读的是 `Stat`，两者不互相覆盖。

## 6. ADR-005：设计令牌按硬件语义命名

**决定**：颜色不叫 `primary/secondary`，而叫 `bus`（数据总线，蓝）、`ctrl`（控制信号，紫）、
`reg`（寄存器，青）、`alu`（ALU 运算，橙），另有 `ok/err/warn`。

**理由**：Phase 4 的所有动画都由数据类型驱动。颜色如果只是装饰，动画就只能靠人肉指定
「这条线用蓝色」；颜色如果承载语义，`trace.dataType === 'control'` 就能直接映射到
`var(--color-ctrl)`，加一种数据类型不需要改十个组件。

主题强调色 `--accent` 通过 `:root[data-accent]` 切换，只影响导航高亮、按钮与光晕，
不影响上面四类语义色——语义色是「物理事实」，不该被用户偏好改掉。

## 7. ADR-006：Monaco 本地打包（Phase 1 已落实）

**决定**：不引入 `@monaco-editor/react`（已卸载）。直接持有 `monaco-editor` 实例，
在 `useEffect` 里动态 `import('./monacoRuntime')`，并显式配置 `MonacoEnvironment.getWorker`。

**落地时踩到的两个坑**（写下来，免得下次重踩）：

1. **worker 路径**：monaco 的 `package.json` 把 `"./*"` 映射到 `"./esm/vs/*.js"`，
   所以必须写 `monaco-editor/editor/editor.worker?worker`；
   写 `monaco-editor/esm/vs/editor/editor.worker?worker` 会变成双前缀，构建直接失败。
2. **语言服务体积**：`editor.main` 顺带引入 CSS/HTML/JSON/TS 四种语言服务，
   产出 `ts.worker`（6.9MB）等四个永不请求的文件。`vite.config.ts` 里加了一个
   `resolveId` 插件，把 `languages/features/*/register.js` 置空——**相对导入用别名拦不住**。
   dist 因此从约 25MB 降到 5.3MB。

**为什么不用 `editor.api` + 手工挑 contrib**：能再省约 40%，但要维护一份 70 行的
contrib 清单，且漏掉某个 contrib 只会在运行时静默丢功能。留到 Phase 10 用实测覆盖后再做。

**验收方式**：`vite preview` 起生产产物，CDP 实测——Monaco 挂载、20 个着色 token、
键盘输入可写入、控制台无错误。

## 7b. 补记：舞台坐标系按「它要被放进去的地方」设计

**决定**：数据通路的 `viewBox` 定为 540×378，缩放接近 1:1。

**理由**：首版按 980×660 画，塞进约 590px 的中央面板后缩放只有 0.5，
11px 的模块名渲染成 4.7px，图上什么都看不清。图形尺寸必须对着目标容器设计，
而不是对着「一张纸」设计。代价是模块框变窄，文案必须精简到 2 行以内。

**连带规则**：连线标签的位置是坐标的一部分，改任何模块坐标都要重新检查标签是否压到框
（写回总线那次就是这么压到 CONDITION CODES 上的）。Phase 4 加高亮时只改 wire 的
`stage` 字段，不再动几何。

## 7c. 补记：面板尺寸只有一个数据源

**决定**：常态下宽度直接读 store；拖拽期间用一份 `draft`，松手提交后丢弃 `draft`。
不在 effect 里把 store 镜像到本地 state。

**理由**：镜像同步会引入「两份真相」，窗口变化或设置重置时容易出现互相覆盖；
每帧写 localStorage 也会卡。拖拽中的尺寸滚动记录在 `dragRef` 上，
既避开了渲染期读写 ref，也让松手时能拿到最新值。

## 8. ADR-007：占位页不放假数据

**决定**：未实现的模块只展示「将构建什么 / 为什么还没到」，不摆示例寄存器值、不播占位动画。

**理由**：这是教学产品，可信度就是产品本身。一个页面只要出现过一次假数据，
用户之后就无法判断哪个数字是真的。宁可空，不可假。

## 9. 内存模型（Phase 2 已落实）

- `Uint8Array` 承载，默认 64 KiB，构造时可变；
- 小端读写显式实现（`readWord` 从高地址往低地址拼），不依赖宿主字节序；
- 越界检查针对**整个跨度**：`readWord(size - 4)` 必须失败，只查首字节会放过它；
- 越界抛 `AddressError`，由执行层捕获并置 `Stat = ADR`；不静默返回 0——
  静默的 0 会让「越界」这个教学重点彻底消失；
- 访问历史走订阅（`onAccess`），内存自己不保留日志数组，避免长程序把内存撑爆；
- `peek` 用于视图渲染，不触发访问通知：界面刷新不是真实访存，不该污染统计。

## 9b. ADR-010：ISA 表是唯一事实来源

**决定**：`src/core/isa/instructions.ts` 一张表定义 27 条指令的 `icode`/`ifun`/形态/长度/
条件/语法/说明。汇编器、解码器、Monaco 高亮、降级视图全部从它派生。

**理由**：这三处原本各有一份助记符名单（Monaco 的 `MNEMONICS` 字符串、`CodeSurface`
的 `Set`、汇编器的 switch）。新增一条指令时漏改一处，症状是「写得出来但不高亮」或者
「高亮了却汇编报未知指令」——都是很难联想到根因的小 bug。Phase 2 已把两份名单删掉，
改为 `ALL_MNEMONICS`。

**连带规则**：编码长度由操作数形态推导（`FORM_LENGTH`），任何地方都不要再写 `10`。

## 9c. ADR-011：RNONE 在解码层宽容、在汇编层严格

**决定**：

| 层 | 行为 |
| --- | --- |
| 解码器 | 照实记录 `rA` / `rB` 半字节，即使它是 0xF 或不该出现的值 |
| 汇编器 | 只接受 15 个真实寄存器名，绝不生成无意义的 0xF |
| 寄存器文件 | `read(RNONE) = 0`，`write(RNONE)` 空操作 |

**理由**：`0xF` 是 ISA 定义的「无寄存器」，硬件确实会读这个字段（`irmovq` 的 valA
读了就丢）。解码时「纠正」它，会让「改了一个字节为什么行为不变」变得无法排查。
而语义层的两条规则正好是教材 `dstE != RNONE` 的写法，SEQ 与 PIPE 各写一遍必然会漂移。

**代价**：`decode` 的返回值不能直接当「合法程序」用。合法性判断留给执行层：
`irmovq` 的 rA 非 RNONE 时，语义上无害（valA 会被丢弃），不报错。

## 9d. ADR-012：汇编器两遍扫描，不做迭代

**决定**：第一遍按指令长度推进地址并建标签表，第二遍解析符号并编码。

**理由**：Y86-64 是定长编码——跳转 9 字节、立即数 10 字节，长度与符号值无关。
因此第一遍就能算准所有地址，两遍必然收敛。若换成 x86 那种变长指令集，这条不成立，
需要迭代到地址稳定。这个差别本身就是一个值得讲的知识点，所以写在代码注释里。

**诊断策略**：不抛异常、不在第一个错误处停下。所有问题收集进 `Diagnostic[]`，
按行号排序返回；有错的指令**仍然占地址**（长度由形态决定），否则后续所有标签
都会错位，用户会看到一串由第一个错误引发的假错误。

## 9e. ADR-013：六阶段是纯函数，SEQ 只做组装

**决定**：`src/core/execution/*` 每阶段一个纯函数，输入「机器状态 + 已译码指令」，
输出该阶段的全部信号；`SEQProcessor` 只负责按顺序调用并提交结果。

**理由**：如果六阶段写成 SEQ 的私有方法，PIPE 想复用就只能复制一份，而两份实现
必然在某个边界条件上分叉——`popq %rsp` 的 `dstE`/`dstM` 先后顺序、`subq` 的 OF
计算都是这种边界。分叉之后「验收 D 对拍」就失去意义：对拍只能证明两边错得一样。

**连带规则**：任何指令语义改动只允许发生在 `execution/`，SEQ 与 PIPE 都不许出现
`switch (icode)` 形式的算术实现。

## 9f. ADR-014：流水线寄存器是最小必要集合

**决定**：`PipeSlot` 只保存该段后续真正要用的字段，不保存整条指令对象。

**理由**：流水线寄存器在硬件里就是一组锁存器，每多存一个字段就多一份「这一拍到底
传递了什么」的歧义。字段少也让轨迹快照便宜——12 拍轨迹可以随手留在 store 里。

**代价**：想显示「F 段这条指令的源码行」时，需要从 `predPC` 反查 `addressToLine`，
不能直接读指令对象。这个换算放在视图层，不进引擎。

## 9g. ADR-015：分支预测「总是跳转」，且错误恢复在 E 段

**决定**：`jXX` 一律预测跳转；E 段算出 `Cnd=0` 时用 E 的 `valA`（即 `valP`）作为
下一 PC，同时给 D 段插气泡。

**理由**：这是教材 PIPE 的做法，也是教学上最容易讲清楚的一种——预测错误时，
已经取进来的那条指令必须作废，而它的地址恰好就在 E 段的 `valA` 里，不需要额外
保存一份「备用 PC」。代价是循环退出时必然错一次（每段循环 1 个气泡），
在长循环里摊薄后 CPI 仍接近 1。

**实测**：20,000 次迭代的循环，CPI 1.0002，气泡 1 个，转发 20,001 次。

## 9h. ADR-016：历史用「寄存器整快照 + 内存撤销项」

**决定**：每条历史存 `before/after` 两份 `MachineSnapshot`（pc + 15 个寄存器 + cc +
stat + cycle），内存改动单独记 `memoryUndo`。

**理由**：最初考虑差分，但差分回退要靠重放，而重放一旦与原路径有任何不一致，
Step Back 会**静默**偏离真实历史——这种错误比多占几 MB 严重得多。
单条历史序列化后约 0.4KB（15 个寄存器 + pc/cc/stat/cycle），40,003 条约 16MB（估算值，
按序列化体积推得，未做堆采样）；整块 64KB 内存进快照会到 GB 级。
性能测试里有用例直接断言单条历史序列化后小于 1.2KB，专门拦这个回归。

## 10. 测试策略

| 层 | 位置 | 关注点 |
| --- | --- | --- |
| 字与状态 | `tests/core` | 补码、符号扩展、越界、常量边界 |
| 指令语义 | `tests/isa` | 27 条指令编码 ↔ 解码往返一致；条件真值表；诊断文案 |
| 汇编 | `tests/assembler` | 三个验收程序的逐字节断言、标签解析、错误恢复 |
| 执行 | `tests/seq` | 验收 A/B/C、栈与调用、异常、Step Back、复位 |
| 对拍 | `tests/pipe` | 8 个程序 SEQ/PIPE 终态全等 |
| 性能 | `tests/perf` | 长程执行时长、复杂度不退化、历史内存上限 |
| 视图 | `tests/ui` | 导航、空读数、执行后的真实数值、汇编输出 |

原则：**测状态，不测像素**。动画是否流畅交给人工验收，数值是否正确交给断言。
