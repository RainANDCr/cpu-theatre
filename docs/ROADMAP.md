## 关键依赖关系

```
02 指令集 ──► 03 SEQ ──► 04 可视化 ──► 05 调试
                 │
                 └──► 06 PIPE（复用同一份指令语义）──► 07 PIPE 可视化
08 逻辑实验 ──► 09 学习中心（每个演示都要有真实引擎可嵌）
```

- **03 之前不要做 04。** 没有真实状态，动画只能编，编出来的东西在 05 会被全部推翻。
- **06 必须复用 02 的指令语义。** 一旦 PIPE 自己实现一套译码，用例 D 就永远对不上。
- **09 放最后**，因为它引用的每个演示都依赖前面的模块。

## 已知风险

1. **对拍成本**：SEQ 与 PIPE 的状态表示若不统一（例如一边用 `bigint[]`、一边用对象），
   对拍会退化成人工比对。Phase 2 就要把 `CPUState` 的字段定义锁死。
2. **历史内存**：长程序 + 每拍快照容易吃内存。Phase 5 的结论是「寄存器整快照 + 内存撤销项」：
   单条约 0.4KB，40,003 条约 16MB（估算），不需要差分。整块内存快照才会到 GB 级，
   已被性能测试拦住。
3. **Monaco 体积**：monaco 约 3MB（gzip 后 ~800KB），必须用动态 import 拆包，否则首屏变慢。
4. **动画与真实性的张力**：为好看而加的过渡会掩盖「这一拍到底发生了什么」。
   规则是：动画时长可以调，动画携带的数据不能假。
